Existing shop assortments

In Mod Wizard, choose Items & crafting > Item in existing shops. The starter creates a visible inventory item, its inventory content set and two actions in Game Feature Data: Add Inventory Content and Add Shop Content. Keep both actions. The second action adds an offer to ShopAssortment:kletka.shop.default; target ShopAssortment:kletka.shop.small for the smaller shop instead. Keep a direct plugin dependency on ElevatorCore and on any other mod whose public assortment/item you use.

The published catalogue is Config/ModContent/KletkaShopAssortments.json in the ElevatorCore plugin. It lists target IDs and their stable offer IDs, item IDs, base costs, weights and conditional flags. Retail shop Blueprints and private modifier assets are not needed in the ModKit. Do not copy a retail shop Blueprint into your mod.

In Add Shop Content > Changes, choose the operation:

  • Append supplies a new offer with a unique ID, item definition, weight and base cost.
  • Remove needs only an existing offer ID. Removing a profile's required offer is rejected.
  • Replace supplies the complete replacement for an existing offer, including modifiers and conditions. Use it for an offer introduced by another required mod as well.
  • Patch inherits the original offer from the target assortment and overrides selected fields. By default only Base Cost changes. For example, patch ID_FlareGun to change its price without copying or clearing its ammunition modifier. Enable the other override switches only when intended; an overridden empty modifier list clears the modifiers.

Patch inherits from the unmodified target asset, not from another mod's edit. Changes to one offer do not merge across mods: greater Priority wins; equal priorities conflict and block session preparation with an error. A patch of an unknown original ID is rejected. IDs must stay stable across mod releases. Two offers in one assortment cannot sell the same item, because the existing shop prices items by definition.

Weight is relative, not a probability percentage. Zero excludes random selection. Availability queries use the assortment's Shop Tags plus the individual shop's Assortment Context Tags; empty queries are unconditional. Selection remains weighted without replacement, up to three items. A required offer must be unconditional. Existing KLETKA shop actors retain their explicit required-canister override, which takes precedence over a profile's Required Offer.

The host resolves and selects stock once; the existing world items replicate to clients. Base Cost still passes through the existing floor/difficulty/shop/player adjustments and discounts. The contribution does not add a new purchase or save format. Current-session composition stays pinned; activate/deactivate changes between sessions. Deactivation restores the base catalogue for the next session. Session admission includes the KLETKA.Shop compatibility hash; missing items and conflicting offers fail before stock generation.

For your own public assortment, create Le Shop Assortment, author its offers and register the ShopAssortment primary asset type in your Game Feature Data. Keep its generated stable ID when renaming or moving it. Increment Gameplay Revision when referenced modifier/Blueprint behavior changes without changing the offer data. An assortment describes stock; your shop implementation still owns display, spawning and purchases. Test the packaged mod against the matching game release before distribution.
