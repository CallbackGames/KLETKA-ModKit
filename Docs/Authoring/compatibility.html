Compatibility and multiplayer

Supported distribution

The cooking workflow supports Windows content-only Game Features. NativeSdk also provides headers and libraries for editor consumers. Runtime gameplay DLL mods are not part of this distribution.

Console and dedicated-server builds require separate platform validation. Provider authentication and DLC ownership also need testing with the intended accounts.

Configured gameplay phases

Install a Gameplay Phase Bindings component on GameState through Game Feature Add Components before starting the session. Ability classes provide their phase tags. Larger priorities override lower ones; different classes at equal highest priority reject the request. Try Start Configured Gameplay Phase is authority-only, preserves the selected ability's actions and does not restart an already active exact phase. KLETKA supplies Phase.Win and Phase.Dead. The optional quest-completion recipe requests a phase only after real completion; restore does not replay it.

Sessions

The host selects gameplay mods before the session starts. The selection stays fixed during the session and may change between sessions. The server executes authoritative gameplay changes and replicates their results.

Public online sessions also apply the game's trusted manifest policy. Matching file hashes establish content identity; publication approval is a separate requirement.

Before publishing

  • Install and activate the mod in the matching game build.
  • Join as another player, including after the session has started.
  • End the session, change the mod selection and start another session.
  • Save, exit and reload. Check missing-mod and incompatible-version handling.

Keep published ContentIds and persistent save identifiers stable. Version schema changes and provide a supported migration when saved data changes.
