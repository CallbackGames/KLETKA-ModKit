Open Tools → Create Atlas Content for the same linked-content recipes used by the game editor. Select a Game Feature, choose a recipe and run Preview before Create Linked Assets. Interactive variants require a working Actor Blueprint and its option; the existing graph and components are preserved.

Resume Save continues a prepared operation after a write failure. Use the same feature and name; keep unsaved drafts open. The journal lists exact outputs and detects changed saved files. Validate Feature checks the selected test Experience; Play Test Map launches a separate process and does not certify gameplay.

Each gameplay system provides its own definitions, components and Game Feature actions.

Public gameplay playground

Open /Game/AtlasExamples/Playground/L_Playground. The map selects its public Experience and GameMode. WASD and mouse control a CharacterMovement character; E uses the canonical interaction manager and the mouse buttons route equipment actions. The sample uses engine shapes and contains no KLETKA game art. Its editable Blueprints show the component composition. For a new copy, run Tools/CreatePlayground.py in a fresh unattended editor with public AtlasGameplayWorldSettings selected for new maps.

Starting assets

  • /AtlasFoundationExample/Foundation: settings and saved variables. The game must provide settings presentation and a Global save profile that accepts mod fragments.
  • /Game/AtlasExamples/DA_Equipment, DA_HitscanWeapon, DA_Interaction and DA_SettingsCatalog: configure their values for your mod.
  • /Game/AtlasExamples/NPC/BP_Guard: an NPC authoring example.

The game supplies equipment and ability components, crafting stations, interaction execution and NPC spawning. The inventory example creates configured station and ingredient-pickup Blueprints; place them in a host map and add its interaction/visuals. Cosmetic definitions do not grant account entitlements.

Local multiplayer

The public playground supports a listen server and additional PIE clients through the engine IP driver and NULL subsystem. Choose Play As Listen Server and two players. This tests gameplay replication; Steam/EOS authentication, invitations, entitlements and voice still require the matching game/provider environment.

Floors

Use ordinary Engine WorldSettings and an Actor with the ElevatorCore component Le Floor Layout (ULeFloorLayoutComponent). Find it in the Actor Blueprint's Add Component menu. The generated example is /AtlasFloorExample/FloorExample/BP_FloorLayout. Register floor content through ElevatorCoreContent and Add Floor Content.

Gameplay tags

Declare tags under a supported extension root: <Root>.Mod.<CanonicalContentId>.<Name>. In Config/Tags/PluginName_Topic.ini, use GameplayTagList= and GameplayTagRedirects= without a leading +. Redirects must stay within your namespace and point to a declared final name.

Tag reference lists available roots, matching rules and multiplayer behavior. The manifest example shows the mod metadata format.
