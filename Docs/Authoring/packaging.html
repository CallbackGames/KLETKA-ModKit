Package and install

Build and play from the editor

In the Mod Wizard, choose Release → Cook & Publish... to open Content, Cook & Publish: your current Game Feature is selected automatically. The same panel is available from Tools → Create Atlas Content. Select your Game Feature and the installed KLETKA executable in Packaged Game. This path is saved in your editor preferences.

  1. Save the feature and its assets. Choose Cook Mod. The tool checks the installed game's registry and selects its matching delivered cooking base automatically.
  2. Choose Build Status for the job result and diagnostic paths. A failed cook, changed source asset or changed game version prevents installation.
  3. Choose Install Test Copy. The native installer creates an isolated copy and records its rollback journal; your normal mod installation is unchanged.
  4. Choose Launch Game. Each launch has a separate user/save directory. Enable the mod in the game's Mods menu and include it when hosting. Process launch alone does not confirm activation, gameplay or network compatibility.

For automation, CookContentMod.py exposes the same DLC cooker. Run python Tools/CookContentMod.py --help for its path arguments.

To target Linux, declare a Linux artifact in your mod manifest and use --platform Linux --base-release-root Releases --base-release RELEASE_NAME with the Linux base for your game.

The AssetRegistry SHA256 must match the receiving game. A different base is rejected even when the editor versions match. Never copy a registry between releases to bypass this check.

Install

Deliver the generated Package directory in full: plugin descriptor, manifest, receipt, Pak/IoStore containers and tag files. Loose project configuration is unsupported. Restart the game before replacing a version whose containers are already mounted.

Export Authoring Files shares editable source assets. Use the cooked Package for installation in the game.

Publication

  1. In Content, Cook & Publish, select the saved Game Feature and its store. Use Cook Mod with the intended game installation.
  2. For the first upload, leave the item ID empty. To update an existing item, enter its ID and confirm the target. The wizard remembers each store's item ID for this mod on this machine.
  3. Choose Publish Privately..., review the game base, version and destination, then confirm. Steam Workshop uses the signed-in Steam client. For mod.io choose Steam or email. The email sign-in prompts for the code inside the upload window.
  4. When the upload completes, use Open store item to inspect the private page. Download the mod on a test installation and check activation, hosting, joining and save recovery before changing its visibility.
  5. For a new version, keep the ContentId, increment Version, save and cook again. Enter the existing ID for this store, confirm the target and choose Update Existing Release.... Verify the same ID, version and page visibility. Repeat with the other store’s own ID if you maintain both.
  6. For offline distribution, choose Manual and Export Bundle to produce a Windows ZIP.

Keep the same canonical ContentId on both services. Store IDs differ; publishing to Workshop does not make a mod available on mod.io or consoles. Only platforms actually built and tested may be selected. Native gameplay DLLs are not supported by this content package route.

Interrupted installation

Inspect the reported AMSInstallAttempts directory. Restore Previous restores a missing destination; it keeps an existing installation intact.
